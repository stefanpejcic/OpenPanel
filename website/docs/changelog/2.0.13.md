### 💡 New
- `opencli domains-test <DOMAIN>` tests why a website is slow: times the page through public DNS, Caddy + WAF, Varnish, the webserver, php-fpm and PHP without cache, checks the database, container limits and settings, and shows the biggest issue with a fix.
- OpenAdmin > Settings > OpenPanel > Display has a new *Applications shown on Dashboard* option to pick which apps show in the Websites section on the OpenPanel Dashboard, and in what order (for example `wordpress n8n nodejs python`). Saved as `applications_dashboard_items` under `[PANEL]` in `openpanel.config`, default is `websites wordpress autoinstaller`.
- OpenAdmin: all pages with tables can now be sorted by clicking the arrows next to the column names.

### 🐛 Bug Fixes
- `opencli waf update` could bring back rulesets disabled in OpenAdmin > Security > CorazaWAF when the update changed them. They now stay disabled.
- *Check passwords against Weakpass.com* never rejected any password, and it used a list of English words instead of a Weakpass list. It now checks against the Weakpass top 1 million common passwords when creating users, and also on password changes and resets from `opencli user-password`, OpenAdmin > Users > Edit and OpenPanel > Account / Forgot password.
- `opencli` always exited with code 0, even when the command failed, so OpenAdmin API calls such as creating a user or changing a password reported success when they failed. It now returns the command's exit code.
- `opencli user-password` reported success for a username that doesn't exist. It now fails with *User does not exist*.
- `opencli user-transfer` (OpenAdmin > Users > Transfer to another server) now moves the whole account: all domains instead of only the first, WordPress/Node.js sites, containers that start on the new server, the password, email accounts and mailboxes of every domain merged into the destination instead of overwriting it, DKIM, MCP tokens and FTP accounts without a false error.
- `opencli server-migrate` (OpenAdmin > Server > Migrate) did nothing when started from OpenAdmin, `opencli` showed the help because of the `-h` flag. The migration now also leaves a working server behind: containers start on the new server, the panel database is copied with a dump, the old IP is replaced in the stack and Caddy configuration, subuid ranges, mailboxes and quotas are kept, and the OpenPanel container is no longer left missing after the restart.
- OpenAdmin: server migration, account transfer, backup import, account export and *Update now* were killed when the OpenAdmin service restarted, and a finished migration kept showing as running. They now run in their own systemd unit.
- OpenPanel: toggling WAF for a domain and changing the account password left a zombie `opencli` process behind.

### 💅 Polish
- CorazaWAF no longer inspects response bodies (`SecResponseBodyAccess Off` in `/etc/openpanel/caddy/coraza_rules.conf`), which added about 230 ms to every HTML page. New installs get it from `opencli waf enable`, existing servers from the 2.0.13 update and it takes effect on the next Caddy restart. Blocked requests still show their rule IDs in the WAF log.
- `opencli waf enable` now disables the OWASP CRS rulesets for Java, Ruby and IIS (`REQUEST-944`, `RESPONSE-952`, `RESPONSE-954`, `RESPONSE-956`), which OpenPanel stacks don't need. They can be re-enabled from OpenAdmin > Security > CorazaWAF.
