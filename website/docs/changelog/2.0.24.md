Released on November 13, 2026

### 💎 New Features
- OpenPanel > Security > ImunifyAV: users get ImunifyAV's own interface, logged in as themselves, plus a summary of infected files and scans with a button to scan the account. Enable the new `imunifyav` module in *OpenAdmin > Settings > Modules*; it needs ImunifyAV installed.
- opencli: `opencli imunify install` mounts the ImunifyAV agent socket into the `openpanel` container, enables the `imunifyav` module and runs a second ImunifyAV UI for the user panel (`imunify-gui-panel` service) that only answers OpenPanel. `opencli imunify start`, `stop`, `status` and `uninstall` manage it too, and it only runs while the `imunifyav` module is enabled, which OpenAdmin now starts and stops like ClamAV for `malware_scan`. Servers that already have ImunifyAV get the module enabled by the update.
- OpenAdmin > Users > *user* > Volumes: new tab listing the user's podman volumes with their purpose, description, size, created date and which containers mount them and where; click a volume for its host mountpoint, driver, labels and options.
- [WordPress plugin and theme profiles #1318](https://github.com/stefanpejcic/OpenPanel/discussions/1318): admins create named plugin and theme sets (e.g. E-commerce, Blog) in *OpenAdmin > Settings > Custom code > WordPress profiles*, and users pick one, the default sets or a clean install with no extra plugins and themes on the WordPress install form. The existing global sets stay as the default, there are no profiles until an admin adds one. The install API takes the same choice as `wp_set`.

### 🐛 Bug Fixes
- [csf doesn't block ssh flooding #1349](https://github.com/stefanpejcic/OpenPanel/issues/1349)
- OpenPanel > WordPress > Install: lines starting with `#` in plugins and themes sets are skipped as comments, as the docs say, instead of being passed to WP-CLI as a plugin or theme to install.
- OpenAdmin > Users > *user* > Storage: images now only count the ones the user pulled themselves, the shared images every user gets from root's image store are no longer added to the user's disk usage.
- [admin panel accessible through ports 443 and 2087 at same time #1348](https://github.com/stefanpejcic/OpenPanel/issues/1348)
- [Custom message for user [object HTMLInputElement] saved successfully. #1327](https://github.com/stefanpejcic/OpenPanel/issues/1327)
- [Bug in OpenPanel UI on /services/&lt;any&gt;  'Click to disable' button not visible on light mode #1335](https://github.com/stefanpejcic/OpenPanel/issues/1335)
- [Bug in OpenAdmin UI: update log not recorded in full #1340](https://github.com/stefanpejcic/OpenPanel/issues/1340)
- `opencli update` keeps the full update log in `/var/log/openpanel/updates/` again. `opencli server-logrotate` ran mid-update and its logrotate rule deleted the log, leaving only the last few lines, and every update log was wiped on each rotation instead of only those older than 90 days.
- `opencli server-logrotate` no longer deletes all reports in `/var/log/openpanel/admin/reports/` every day, only those older than 7 days.
- opencli: `opencli imunify install` after `opencli imunify uninstall` brings the ImunifyAV interface and its settings back. Uninstall removed the UI files and config layers but kept the packages, so the interface stayed empty and ImunifyAV ignored the scan limits and the setting that lets users start scans.
- OpenPanel > Login: the background pattern shows on the login page again, the redesign's lighter page colour hid it.
