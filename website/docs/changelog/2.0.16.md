### 🐛 Bug Fixes
- `opencli sentinel` OOM alerts now list the killed processes with user, PID, container, memory and time instead of only a count, and kills inside users' rootless containers are no longer left out of the details.
- `opencli docker-backup` no longer fails for accounts using the default `backup.env`, its values are now unquoted since podman passed the quotes on to the backup container (`'true'` for `BACKUP_FILENAME_EXPAND`).
- `opencli docker-backup` backups now restore vhost files from the Backups > Restore page, they were silently skipped because the restore looked for the wrong volume name.
- `opencli docker-backup` now backs up PostgreSQL databases as `pg_dump` dumps instead of copying the live data directory, so they can actually be restored from the Backups > Restore page.
- `opencli docker-backup` no longer packs the full account archives from `opencli user-backup` into every nightly backup, `.tar.gz` files are now excluded by default in `backup.env`.
- `opencli docker-backup` MySQL/MariaDB dumps now use `--single-transaction` and include routines, triggers and events, and one failing database no longer stops the remaining ones from being dumped.
- `opencli docker-backup` now actually backs up emails: with an email storage location set, the backup only stored links to each domain's mail folder, so each domain's mailboxes are now mounted into the backup (`opencli domains-add`/`domains-delete` keep the mounts in sync and the update adds them for existing domains).
- `opencli domains-delete` no longer removes the mail links of all the user's other domains.
- Restores from Backups > Restore no longer follow symlinks inside the account's volumes, so a restored file can't be written outside of them.
- `opencli domains-unsuspend` now removes the domain's saved copy from `suspended_domains/`, before it stayed there and `opencli domains-suspend` refused to suspend the domain again ("Domain is already suspended."). `domains-suspend` now checks the live Caddy file, and the update removes copies left behind for domains that aren't suspended.
- Restoring a database from Backups > Restore now streams the dump into the database container instead of loading it into memory, so large dumps, triggers, procedures and PostgreSQL `COPY` data restore correctly, and restoring `wp` no longer picks up `mywp.sql`.

### 💡 New
- `opencli docker-backup` now adds a critical "Backup failed" notification when backups fail for any user, toggled with the new `docker_backup` key in notifications.ini or OpenAdmin > Settings > Notifications.
- `opencli docker-backup` archives now start with a `backup/00-meta/` folder listing the dumped databases, so Reindex Destination reads only the start of each archive instead of downloading it, and skips archives that are already indexed. Older archives no longer list a site's own `.sql` files as databases.
- Backups > Restore is redesigned: it opens with backup stats and a tile per type (Everything, Website Files, Databases, Emails, Domains, Cron Jobs), and each type lists its own backups so you can restore just what you need. The Databases tab lists each database once with an older-backup picker and restores several at a time, and any restore that brings back cron jobs now restarts the cron container so they take effect.
- `opencli docker-backup` now backs up the DNS zone of each domain, and restoring a domain from Backups > Restore brings its DNS zone back too.
- Backups > Restore can now restore single items, reading only as much of the archive as needed: website files and folders (with a folder browser and single file download), and email accounts and domains listed once across all backups like databases, with a picker for older backups. Virtual Hosts is now Domains: restoring a domain brings back its VirtualHost, PHP version and DNS zone, a domain you deleted is added back to your account first, and suspended domains can't be restored. Selected databases, email accounts and domains can also be downloaded on their own (a single database as its `.sql` dump).
- Backups > Restore now restores in the background through a queue, one restore at a time per account (restores through the API wait for it too), and shows the queue and a log of the latest restores with their result and duration.
- Backups > Restore now shows the size of each backup and of each database dump in it, also returned as `size` and `database_sizes` by `/api/backups/list`.

### 💅 Polish
- For accounts with admin-configured backups, the Backups page now opens Restore & Download directly since there is nothing to configure.
- Downloading a backup from Backups > Restore now streams it straight from the destination instead of saving a temporary copy first.
