### 🔒 Security
- PHP security releases of 19 November 2026 ([announcement](https://www.php.net/archive/2026.php#2026-11-18-1), critical, all supported versions): the update pulls the new build of every PHP image the accounts use, `openpanel/php-fpm` and `shinsenter/php`, and of phpMyAdmin, and recreates the running containers on it. Roundcube is recreated on its new image without restarting the mail server. Nobody is moved to another image, and a container is only recreated once its image really has the fixed PHP. It runs in the background, follow it with `tail -f /var/log/openpanel/updates/2.0.27-php.log`. New option `opencli docker-update --no-php-move`.
- Sentinel firewall (CSF) is updated to [15.17](https://github.com/sentinelfirewall/sentinel/releases/tag/15.17) on servers where it's installed and older: fixes CVE-2026-65638 and CVE-2026-65639 (command injection), and installs the fixes of 15.15 and 15.16 that earlier upgrades left out. `csf -u` on servers installed before 15.16 checks an address that no longer gets releases, so the update reinstalls it, keeping `/etc/csf` and the OpenPanel `csfpre.sh`/`csfpost.sh` rules. The previous config is kept in `/root/csf-backup-<date>`.

### 💎 New Features
- OpenAdmin > Settings > OpenPanel: every option has a help tooltip that explains what it does.
- The WordPress plugins set, themes set and profiles moved from OpenAdmin > Settings > Custom Code to a new [WordPress section on OpenAdmin > Settings > OpenPanel](/docs/admin/settings/openpanel#wordpress).
- OpenAdmin > Settings > OpenPanel > WordPress: the default plugins and themes sets are shown side by side, and several WordPress profiles can be added in one save with **+ Add another profile**.
- OpenAdmin > Dashboard > Daily summary: the page only opens a file saved each morning at 06:45 by the new `openadmin daily-summary` command (on a multi-server master with every server's part), nothing is worked out when it's opened. Days are kept for 30 days, a day can be made again with `openadmin daily-summary --date YYYY-MM-DD`. [Docs](/docs/admin/daily-summary/)
- OpenAdmin > Dashboard > Daily summary: new **Slowest websites** section with the lowest PageSpeed scores from that day's checks, `opencli websites-pagespeed` keeps a copy of every report per day for 35 days.
- OpenAdmin > Dashboard > Daily summary: new **Web firewall** section with the requests blocked that day, the top rules, the most attacked websites and the blocked addresses, with the visitor's real IP and country also behind Cloudflare.
- OpenAdmin > Dashboard > Daily summary: websites show their favicon (Busiest websites, Needs attention), databases the MySQL or MariaDB logo, and several admins logging in from the same new IP are one alert row.
- Sentinel: the *SYSTEM REBOOT!* notification says why the server went down (power button pressed from outside by the provider or the host node, reboot or poweroff command, unattended-upgrades, kernel panic, freeze, power loss) and how long it was down.
- Sentinel: `openadmin_ftp` only runs while at least one FTP account exists, the first new FTP account starts it again.
- OpenPanel > PHP > Domains and `opencli php-domain`: changing a domain's PHP version moves that domain's cron jobs (a Host header, URL or path in its document root) from the old php-fpm container to the new one.
- Multi-server: the Google PageSpeed API key is synced with the SMTP, captcha, AI and Cloudflare keys.
- OpenAdmin > Security > AI & Bot Control: every column of the **Per-site AI crawler policies** table can be sorted, also across the servers of a cluster. The module badge, the **Enable module** button and the policy explanation left the page header, the policies are explained in the [docs](/docs/admin/security/bot-control/#policies).
- OpenAdmin > Settings > OpenPanel and Settings > Defaults: after a change a bar at the bottom right says there are unsaved changes, with **Discard** and **Save changes**, like on Settings > Modules.

### 🐛 Bug Fixes
- OpenAdmin > Accounts > Create: the progress could freeze on "Configuring rootless Podman" while the account was still being created. OpenAdmin cut every response after 30 seconds, and a container image download printed a progress line longer than the page could read.
- OpenAdmin > Settings > Notifications: the toggles for newer alerts couldn't be saved on servers whose notifications.ini didn't list them yet.
- OpenAdmin > Settings > General: switching dev mode back off before restarting OpenAdmin was ignored, and the page kept showing the old value.
- OpenPanel login page: the favicon set on OpenAdmin > Settings > OpenPanel was not used.
- Forbidden usernames and restricted domains: the last entry was ignored when the list didn't end with a new line, and entries saved from the browser could fail to match.
- OpenAdmin > Server > SSH: password authentication, public key authentication, root login and port were ignored on servers where a file in `/etc/ssh/sshd_config.d/` (like cloud-init's) set them, and a setting missing from `sshd_config` was never written. They are now also saved in `sshd_config.d/00-openadmin.conf`, checked with `sshd -t` before SSH restarts, and the page shows what SSH actually uses.
- OpenAdmin > Services > Limits: a new CPU or memory limit only took effect when the service was recreated. It's now applied to the running container right away, the message lists which ones.
- OpenAdmin > Settings > Modules: switching off SSL, Redirects, PHP Options, PHP INI editor, PHP Extensions, phpMyAdmin, Edit VirtualHost, Document root, Domain logs, Capitalize domains, Domain suspend or Temporary links had no effect, users kept them as long as their feature set had them. They are now removed for users like every other module. New installations have them switched on, on existing servers check Settings > Modules after updating.
- OpenPanel > FTP: the plan's FTP account limit was shown on the dashboard but not enforced, users could create any number of FTP accounts. Creating one over the limit is now refused, also through the API.
- OpenAdmin > Settings > Notifications: an alert that wasn't in `notifications.ini` yet showed as off, saving the page then turned it off for real. The Admin/Reseller deleted, Reseller renamed, OpenAdmin port changed, User near or over disk limit and Docker image update failed alerts can now be turned off too.
- OpenAdmin > Settings > Locales: a new default locale reached users only after up to 24 hours.
- OpenAdmin > Settings > Custom Code > Before startup: the script never ran, it was saved in `/root` which the OpenPanel container doesn't mount. It's now kept in `/etc/openpanel/openpanel/custom_code/run_on_startup`, an existing script is moved there.
- OpenAdmin > Settings > General: a new `/openpanel` path or OpenPanel/OpenAdmin port didn't take effect, Caddy wasn't reloaded and the new port wasn't opened on the firewall.
- OpenAdmin > Settings > Modules: enabling Dynamic DNS also set up BIND monitoring as if the DNS module was on.
- OpenAdmin > Settings > OpenPanel > Logout URL had no effect, OpenPanel read a different config key. It now redirects users there after logout.
- OpenAdmin > Emails > Settings: changes such as turning POP3 off never reached the mail server, Roundcube depends on it so podman kept the old container. It's now recreated with Roundcube.
- OpenAdmin > Emails > Accounts: lifting a send or receive restriction kept rejecting mail until the mail server restarted, Postfix is now reloaded after every change.
- OpenPanel > Domains > New: after an error the log with the reason (e.g. domain limit reached) no longer opened on its own.
- OpenPanel: pages always said `<html lang="en">`, now they carry the user's language so screen readers and browser translation get it right.
- OpenAdmin > Domains > DNS: Delete zone and Restore default zone did nothing, the command waited for a y/n on the terminal and timed out.
- OpenAdmin > Domains > DNS: a zone created again after being deleted was never served, it wasn't added back to BIND's config.
- [Goaccess: No authentication provided. #1358](https://github.com/stefanpejcic/OpenPanel/issues/1358)
- `opencli php-listen`: switching between port and socket left php-fpm on the old mode with podman-compose 1.0.6, the containers were only restarted and the websites returned 502. Containers are now recreated, only the ones that already run, and suspended accounts are found by their own name.
- OpenAdmin > Dashboard > Daily summary: the account backup showed "The scheduled backup didn't run" once logrotate had moved the day's run to an older log.
- OpenAdmin > Backups > User backups: a schedule set on Scheduled actions (e.g. `0 22 * * *`) showed as Disabled and hid **Run backup now**, saving the page then really turned the backups off. It now shows as Custom and saving keeps it.
- Multi-server master: `opencli docker-backup`, quota, daily summaries, error reports and scans also got the other servers' accounts, for example the backup log said they "manage their own backups".
- OpenAdmin search box: users and websites after the first 10 never showed up, now what's typed is looked up on every server of the cluster.
- OpenAdmin > Dashboard > Daily summary: the main problem line now says the share is of the accounts that need attention, not of all accounts.
- Multi-server master: on pages whose title shares a row with badges (e.g. AI & Bot Control) the server picker sat left of the title instead of right.
- Multi-server master: the **Server** column heading took the right alignment of the numbers column next to it while the server names were on the left.
- OpenAdmin > Security > AI & Bot Control: the page took 10-15 seconds with many domains, the access logs are now read in parallel, lines outside the time window are skipped without decoding them and the report is kept for 2 minutes, so sorting the table or opening the page again is instant.
- OpenAdmin > Security > AI & Bot Control on a multi-server master: the Domains, Total requests, AI crawler hits and Blocked totals and the domain picker showed only the master, they now add up every server. Suspended owners show their username in red like in the other tables.
- OpenAdmin > Security > Web firewall on a multi-server master: the domain, mode and stopped request totals, **Most hit domains**, **Rules triggered most** and the Logs tab totals and user filter showed only the master, they now add up every server.
- OpenAdmin > Websites: Python sites had the same generic icon as Docker sites in the type filter and the table, they now show the Python logo.
