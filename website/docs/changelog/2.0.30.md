### 🔒 Security
- OpenAdmin's web terminal now asks for the admin's password before it opens. The websocket only connects with a short-lived token handed out after that check, so an injected script can't open a root shell on its own even if it runs in the admin's browser (defense in depth for GHSA-3mrp-68rg-c3fj).
- OpenAdmin no longer drops logged or account-supplied values into Alpine expressions, where a quote could break out and run code in the admin's browser (GHSA-3mrp-68rg-c3fj). The access log viewer, the dashboard and user activity logs, the global search and every table search filter now treat these values as text or JS-escape them. The worst case was a crafted request URI or a hosting account's favorite link running as root through the admin web terminal. Reported by ozgun kultekin, wakefield (wakefield.co).
- The OpenPanel Redis cache now listens only on its unix socket, not on a TCP port that account containers could reach, so a website can no longer read or change the panel's cache (GHSA-3mrp-68rg-c3fj). New servers get this from the default stack, and existing servers are fixed automatically on update. Reported by ozgun kultekin, wakefield (wakefield.co).

### 💎 New Features
- OpenAdmin > Services > Service limits: a table with one row per system service, showing its live CPU, memory and process usage next to the limit. Click the pencil to change a limit, CPU and memory apply to the running container right away. Columns can be sorted, and the other settings of a service (version, timezone and so on) open below its row, with the version picked from the image's tags on Docker Hub (cached for a day). A limit set to 0, a new version or any other setting the container reads offers a restart, which also recreates the services that depend on it.
- OpenAdmin > Users > Services: column sorting, and clicking a service opens its details (status, restarts, image, networks and IPs, ports, volumes, command, healthcheck). The details have an editor for just that service's `docker-compose.yml` block and the `.env` variables it uses, version variables are a select of Docker Hub tags and ports are read only. The changes are checked before they're saved.
- OpenAdmin > Services > Podman: the Info tab shows an overview of containers, images, storage and the Podman version, with host, runtime and storage details below it.

### 💅 Polish
- Heavy disk work now runs at the lowest CPU and IO priority (`nice -n19`, `ionice -c3`) so it doesn't slow down the websites. Only the idle IO class does anything on the common mq-deadline disk scheduler, so the old `ionice -c2 -n7` steps were moved to it as well:
  - **OpenCLI**: `opencli backup` (system backup archive), `opencli domains-stats` (GoAccess, the priority carries into its container), `opencli files-purge_trash` (size count), `opencli user-backup`, and the rsync copies of `opencli user-transfer` and `opencli server-migrate`. `user-transfer` and `server-migrate` take `--no-throttle` to copy at normal priority, like `user-backup`.
  - **OpenPanel**: the scans of a whole home directory on the Inodes, Disk Usage and Largest files pages. Folder sizes in the File Manager and the Trash size get `nice` only, since the user is waiting on them. The OpenPanel image now includes `ionice` (`util-linux-misc`).
  - **OpenAdmin**: volume sizes on Users > Volumes and the Trivy vulnerability scans on Services > Podman.
- OpenAdmin > Users > Services: CPU, memory and process limits save without reloading the page. Setting CPU or memory to 0 saves it and offers a restart instead of restarting the service on its own, and a process limit of 0 is removed from the running container right away.
- OpenAdmin > Services > Podman: tables, search and tabs line up with the other pages.
- The OpenAdmin service now runs with a stronger bias against the OOM killer (`OOMScoreAdjust=-800`), a small CPU priority (`Nice=-5`) and a reserved CPU and memory share (`CPUWeight=400`, `MemoryLow=128M`), so the control plane stays reachable when the server is under heavy load. New servers get this from the unit template, existing ones on update.
- OpenLiteSpeed: the `lsphp` processor now opens at most as many backend connections as it has PHP children (`maxConns` matched to `PHP_LSAPI_CHILDREN`) and keeps `persistConn` off, so requests don't queue against connections that aren't there. Existing accounts are updated and it takes effect on the next OpenLiteSpeed restart ([#18](https://github.com/stefanpejcic/openpanel-configuration/pull/18)).

### 🐛 Bug Fixes
- [Podman image vulnerability scanner reports numerous high/critical vulnerabilities and updates available on a fresh installation #1379](https://github.com/stefanpejcic/OpenPanel/issues/1379)
- FTP: the first FTP account couldn't be created after sentinel stopped the idle FTP server, `/ftp/new` and the API now let `ftp-add` start it, and active connections show an empty list instead of a 503.
- Backups: WordPress and app backups created the `backups` folders as root in the account's files, so users couldn't delete them and the File Manager showed them as root. They now get the account's owner, and old root-owned `backups` folders are fixed on the next backup.
- New installations use PHP 8.5 as the default version for new users again, WordPress and some app installers fail on 8.6.
- OpenAdmin > Podman > Images: the Trivy vulnerability scan unpacked each image into `/tmp`, which is in RAM on many servers, so scanning large images (Elasticsearch, OpenSearch) could run the server out of memory, and a scan stopped midway left gigabytes behind. Scans now use `/var/tmp/openadmin-trivy` on disk, clean it up after every image and when OpenAdmin starts, and run one at a time at low CPU and disk priority.
- OpenAdmin: containers created or restarted from OpenAdmin ran under the `admin` service, so restarting OpenAdmin also stopped them (for example Redis, or the OpenPanel port 2083). They now run in their own scope like the rest.
- OpenAdmin > Podman > Images: vulnerability results count unique CVEs instead of one row per affected package, and split them into "fixable" and "no fix yet". The details list fixable CVEs first, hide the ones without a fix behind a toggle, and suggest pulling the image when a newer version is available. The update check also compares against every digest the local image has, so it no longer reports an update that's already pulled.
- OpenAdmin > Services: restarting Redis, MySQL, BIND or another service from the main docker-compose.yml kept the old container, because OpenPanel depends on some of them and BIND was looked up under the wrong name, so a changed setting never applied. Restart now recreates the container and the ones that depend on it.
- OpenAdmin > Users > Services: a CPU, memory or process limit was reported as saved even when the variable wasn't in the account's `.env` yet, it's now added there.
- OpenAdmin > Services > Podman > Images: Pull, Update and Download all saved the image only for root, while users' containers read images from the shared store, so an updated image (for example a PHP version) never reached their containers. Images are now pulled into the shared store.
- OpenAdmin and the OpenPanel UI rewrote the webmail master account in the mail server every time they started, which made the mail server rebuild all email accounts and reset the owner of every mailbox on disk. They now only write it when it's missing or its password changed.
- OpenAdmin > Users > Services: accounts created from an older template had their process limits written as a number in `docker-compose.yml`, so a limit changed from OpenAdmin went back to the old one when the service was recreated. Saving a process limit now points that service at its `.env` variable, keeping the old number as the default.
