Released on November 25, 2026

### 💡 New
- MCP and API: deploy a public git repository to a domain in one call (`POST /api/deploy`). OpenPanel detects the stack (Next.js, Nuxt, Vite, Express, Django, FastAPI, Flask, Rails, Spring Boot, static HTML and more), installs it as a Node.js, Python, Ruby or Java app with a reverse proxy, and waits until it answers. `POST /api/deploy/detect` shows the plan first, `GET /api/deploy/status` reports health and logs.
- `opencli user-mcp`: create, list and revoke a user's AI Assistant (MCP) tokens from the terminal, and print the setup for Claude Code, Claude Desktop, Codex, Cursor, VS Code or Gemini CLI.
- AI Assistant (MCP) tokens can now be limited to making changes without deleting anything, and to some features only (for example DNS and Domains). The limits apply to `/api/` calls too, and a limited token can't create other tokens.
- Account > AI Assistant (MCP) shows setup for Codex, Cursor, VS Code and Gemini CLI next to Claude, and fills in the new token right after you generate it.

### 🐛 Bug Fixes
- `POST /api/pm2/<site>/start`, `stop` and `restart`, `GET /api/pm2/<site>/logs` and `PATCH /api/pm2/<site>` used the site name (like `example.com/blog`) as the container name, so they failed for every app. They now look the app up by its site. `PATCH` also matched apps with `LIKE` across all accounts and edited the wrong `.env` keys. `restart` takes `{"no_pull": true}` to skip pulling the image.
- MCP: installing a Node.js, Python, Java, Ruby or Composer PHP app through the AI Assistant sent an empty form, and installers that stream progress were reported as successful even when they failed.
- `GET /api/crons/log` with a negative `lines` value crashed the request. Values below 1 now fall back to 100.
- MCP: deleting a database grant, a DNS record or a cron job through the AI Assistant had no way to send the details these routes read from the request body.
- API docs: fixed examples that the panel would reject, for cron edits (5-field schedule), container create and edit (missing `network` and `image`) and container resources (`512m` was saved as `512mG`).
- Account > AI Assistant (MCP): the Claude Desktop example used a `url` entry that Claude Desktop doesn't read. It now runs `mcp-remote`.
- [AI & Bot Control rate limiting own admin #1366](https://github.com/stefanpejcic/OpenPanel/issues/1366)
- Containers: the CPU, RAM and PIDs limits from the API and the Containers page were written into the account's `.env` unchecked, so a value with a quote and a new line could add other settings, including the protected `TOTAL_CPU`, `TOTAL_RAM` and `USER_ID`. Limits now have to be plain numbers (RAM may end in `G`), the API answers 400 for anything else, and CPU and RAM set on a single container can't go above the plan, as bulk edits already enforced.
- `opencli user-restore`: a container that couldn't be recreated (for example its image couldn't be pulled on a server without internet access) was skipped silently and the restore still reported no warnings. It now checks every container from the backup after starting them, reports each one that isn't running with the image it needs, and prints `Started X of N container(s)`.
- `opencli email-setup-bg chown`: a mailbox named `..@domain` made it run `chown -R` on the whole `/var/mail`, so every mailbox on the server ended up owned by that account. Names that are empty, `.`, `..`, start with a dot or dash, or have characters outside `a-z A-Z 0-9 . _ % + -` are now refused, and `chown` runs without a shell ([#277](https://github.com/stefanpejcic/opencli/pull/277)).
- OpenAdmin > Emails > Queue: with tens of thousands of queued messages the page never loaded (postqueue output of 100+ MB parsed on every load and every row rendered with all its recipients). The queue is now read as it streams, cached for 30 seconds, and shown 100 messages per page with server-side search and a filter per queue (hold, deferred, active).
- `opencli email-server postfwd`: email rate-limiting was never applied. The status only checked that `postfix-main.cf` exists, which it does on every server for other overrides like `message_size_limit`, so it said ENABLED and `enable` did nothing while Postfix never asked postfwd. On a server where `enable` did run, it overwrote `postfix-main.cf` with a template that dropped those overrides and the Dovecot quota check, then used `podman restart`, which skips the mailserver setup. `enable` now adds the postfwd check to the live `smtpd_recipient_restrictions`, keeps the other overrides, applies it with `postconf` + `postfix reload` and sets `smtpd_policy_service_default_action = DUNNO`, so mail still goes out if postfwd is down. `disable` reverts only that.
- `opencli email-ratelimit`: the generated rules counted a fixed text (`rate(<user>_ratelimit/...)`) instead of a request attribute, so postfwd never counted anything and no account was ever limited. Rules now tag each domain's emails with the account and count them in one `limit_<user>_rate` rule, so all domains of an account share the plan's hourly limit. Run `opencli email-ratelimit --all-users` to regenerate existing rules.
- postfwd reset all hourly counters on every reload (after each domain add or rule change), and its 60-second request cache answered repeated identical requests (like a contact form sending to the same address) without counting them. The postfwd service now starts with `--keep_rates` and `CACHE=0`, and `opencli email-server postfwd` adds both to existing `compose.yml` files. Fresh installs also named the container `openadmin_postfwd`, so the reloads, which go to `postfwd`, never reached it. The mailserver's `depends_on: postfwd` is removed too, a mailserver created with it made postfwd impossible to recreate (Postfix doesn't need postfwd to start, it falls back to `DUNNO`).
- `opencli email-ratelimit --domain` and `--delete-domain`: removing the old rule never matched, so `--domain` added a duplicate rule every time and `--delete-domain` removed nothing. Removing rules also stopped only at an empty line, so rules appended without one by a restore or transfer were removed together with the next account's rules.
- OpenAdmin > Emails > Hourly limits: reads and writes the new rule format, editing one domain keeps the other domains of the account.
- AI & Bot Control: the "Blocked / throttled" counts included every 403 and 429 on the site, so a 429 from the site's per-IP rate limit showed up as a blocked visitor on the bot control page ([#1366](https://github.com/stefanpejcic/OpenPanel/issues/1366)). Only AI crawlers count as blocked now, and other visitors' 403s and 429s are shown separately as coming from the site rate limit or the WAF (`other_blocked` in the API). The same applies to OpenAdmin > Security > AI & Bot Control, where they show as "Other visitors" under the card.
- OpenPanel dashboard: apps added to the Websites section from OpenAdmin > Settings > OpenPanel > "Applications shown on the dashboard" (Joomla, Docker, Node.js...) had no icon on the built-in theme, which doesn't load Bootstrap Icons. They now use Remix icons there.
- OpenPanel dashboard: the Git tile was missing from the Websites section on every theme, because the `applications_dashboard_items` default added in 2.0.13 left it out. `git` is now in the default and can be picked in OpenAdmin, and 2.0.29 adds it on servers that still have the old default.
- `opencli user-restore` and `opencli user-transfer` now keep file permissions from the backup ([#1372](https://github.com/stefanpejcic/OpenPanel/issues/1372)). `domains-add` added group write to everything in the restored docroot, so a 0600 `wp-config.php` came back as 0620, and the FTP step set every file in an FTP account's folder to 2775. Both now leave restored files alone and only set up folders they create, through the new `domains-add --keep-permissions` flag.
- `opencli imunify notify`: the scheduled ImunifyAV scan sent a separate "ImunifyAV scan clean" notification for every account. User scans are now combined into one notification for all accounts, sent by email and webhook once the last account is done, and only accounts with malware or a failed scan get their own.

### 💅 Polish
- Deployed apps with a build step (Next.js, Nuxt, Vite and other `npm run build` projects) only rebuild when the git commit changed, so restarting without new commits takes seconds instead of a full build.
- API: MySQL, PostgreSQL, Domains, DNS, Cron Jobs, Containers, Git, Node.js/Python apps and File Manager routes now document every request field with its type, limits and allowed values. The Swagger page at Account > API and the AI Assistant's MCP tools use them, so assistants send the right fields the first time.
- MCP: the server lists a short set of tools plus `search_tools` and `call_tool` instead of all 400, only shows tools the plan allows, and tells the assistant to ask before destructive actions. Set `mcp_tool_search=off` to list every tool again.
- `opencli domains-ratelimit trusted`: IPs in `csf.allow` and `csf.ignore`, loopback and a manual list (`trusted add|remove`) now skip the per-IP and per-domain rate limits. Whitelisting an IP in the firewall had no effect on Caddy, so an admin working in WordPress could still get 429 ([#1366](https://github.com/stefanpejcic/OpenPanel/issues/1366)). A cron job runs `trusted sync` every 5 minutes, and 2.0.29 sets it up on existing servers.
- Installer: without `--swap` the swap file is now sized by RAM (twice the RAM up to 2 GB, 4 GB up to 8 GB of RAM, 8 GB up to 32 GB, none above that), before it was always 1 GB.
